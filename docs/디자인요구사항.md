# 커맨드웨어 등록 앱 디자인 요구사항 (v2)

디자인 덱을 만들기 전에 정리한 요구사항이다. **화면 구조(무엇이 어디에 있는지, 한 화면 작업대 + 아래 시트)는 그대로 두고**, 겉모습(색·글자·모양·아이콘·상태 표현)만 바꾼다. 구조 원칙은 `화면명세서.md`의 P1–P6를 따른다.

> v1과 달라진 점은 맨 아래 8장에 있다. 핵심: 현재 색을 실제로 재 보니 **글자 대비는 이미 괜찮고, 문제는 테두리·막대(1.5–2:1)와 주황·빨강이 비슷한 것**이었다. 그래서 목표 수치와 새 색 값을 구체적으로 정했다.

---

## 1. 범위

| 바꾸는 것 | 바꾸지 않는 것 |
|---|---|
| 색 체계(토큰), 글자 크기·굵기·줄 간격 | 화면 배치, 탭 구성(A–E), 시트 구조 |
| 버튼·칩·카드·막대의 모양(모서리, 테두리, 높이) | 뷰 종류와 위치, 화면 이동 흐름 |
| 아이콘, 상태 표시 방식(색 + 아이콘 + 글자) | 기능, 판정 로직 |
| 화면에 보이는 문구(선택) | 코드의 이름(`pose`, `node` 등), 정보의 양 |

구현할 때 고칠 곳
- XML: `res/values/colors.xml`, `themes.xml`(Cw.* 스타일), `res/drawable/*`, 레이아웃의 `textSize`·`minHeight`
- Java: `Ui.java`의 색 상수와 `pill/round/bar/typeBadge`, 코드에서 정한 글자 크기 10곳(`BodyView` 캔버스 글자 12–13, 흉내 버튼·시트 제목 14 등). **XML만 고치면 모형 위 글자와 코드로 만든 버튼은 그대로 남는다**
- 색은 Java에 숫자로 박지 말고 `colors.xml` 한 곳에서 읽게 바꾸면 어두운 테마(4장)가 쉬워진다

## 2. 사용자: 노인 보호사·간병인

| 특성 | 디자인에 주는 뜻 |
|---|---|
| 40–60대가 많음, 노안 | 작은 글씨(11–13sp)를 못 읽음. 흐린 선·옅은 막대는 더 안 보임 |
| 한 손으로 폰, 다른 손으로 사용자를 부축 (P4) | 엄지로 정확히 누르기 어려움. 버튼이 커야 하고 서로 떨어져 있어야 함 |
| 폰이 아니라 사용자를 봄 (P3) | 화면은 **흘끗 봐도** 상태를 알아야 함. 소리·진동이 주 신호, 화면은 확인용 |
| 스마트폰 앱에 익숙하지 않을 수 있음 | 기술 용어(포즈형, 노드, 슬롯, 민감도) 부담. 아이콘만 있는 버튼은 뜻을 모름 |
| 시설 조명이 밝거나, 밤 병실은 어두움 | 밝은 곳에서 옅은 색이 날아감. 어두운 곳에서 흰 화면이 눈부시고 돌봄 대상을 깨움 |
| 장갑을 끼거나 손이 젖어 있을 때가 있음 | 끌기·좁은 슬라이더보다 누르기가 쉬움 |
| 돌봄 대상 옆에서 씀 | 차분하고 믿음직한 돌봄 기기 느낌. 경고가 늘 떠 있으면 무뎌지고 불안을 줌 |
| 일부는 색약(남성 약 8%) | 빨강·초록·주황을 색만으로 구분하면 안 됨 |

## 3. 필수 요구사항

### R1. 글자 — 크기 단계를 정하고, 커져도 무엇을 지킬지 정한다

| 단계 | 크기 | 굵기 | 줄 간격 | 쓰는 곳 |
|---|---|---|---|---|
| 큰 숫자 | 40sp 이상 | 굵게 | 1.0 | 카운트다운(지금 모형 위 52dp, 유지) |
| 상태 | 22sp | 굵게 | 1.2 | `기준 넘음`, `이탈 1.2/1.5초`, 발동 배너, 녹화 중 |
| 제목 | 20sp | 굵게 | 1.25 | 카드 제목, 선택한 부위, 동작 이름 |
| 본문·버튼 | 16sp | 보통 / 버튼은 굵게 | 1.35 | 설명, 목록 행, 모든 버튼 글자 |
| 보조 | 14sp | 보통 | 1.35 | 시간, 배터리 수치, 도움말 한 줄 |

- 14sp 미만 금지(지금 XML에 11sp 2곳, 12sp 13곳, 13sp 22곳 + 코드 10곳 중 일부)
- 굵기는 2단계만. 얇은 글꼴 금지
- **시스템 글자 130%에서 무엇을 지킬지 우선순위**: 한 화면 구조와 큰 글자가 부딪히는 곳(특히 D의 모형+막대 나란히)에서 다음 순서로 양보한다
  1. 절대 잘리면 안 됨: 상태 글자, 주요 버튼 글자, 경고 문구
  2. 두 줄로 내려가도 됨: 동작 이름, 설정 요약 줄, 안내 띠
  3. 말줄임(…) 해도 됨: 보조 수치(배터리 %, 시간), 모형 위 `R 오른쪽/L 왼쪽` 같은 표시
- 모형 위 캔버스 글자는 모형과 함께 커지고 줄어드는 dp 단위로 두되 최소 14dp

### R2. 대비 — 글자는 7:1, 선과 막대는 3:1

| 대상 | 목표 | 지금 | 판정 |
|---|---|---|---|
| 본문·보조 글자 | **7:1 이상**(노안·밝은 조명) | 보조 글자 `#545B69` 6.3:1 | 약간 부족 |
| 상태·버튼 글자(굵은 20sp 이상) | 4.5:1 이상 | 주요·초록·주황·빨강 모두 5.2–6.6:1 | 통과 |
| 버튼·칩 테두리, 입력칸 | **3:1 이상** | `#C9D0DB` 1.55:1 | **불합격: 안 눌린 칩이 배경과 구분 안 됨** |
| 판정 막대 채움(대기 상태) | 3:1 이상 | 옅은 파랑 `#8EA4DE` 2.0:1 | **불합격** |
| 구분선 | 장식이라 기준 없음 | `#DCE1E8` 1.2:1 | 그대로 |

- 비활성 버튼은 투명도(지금 45%)만으로 표현하지 말고, 회색 + 이유 한 줄(예: `기록 3개부터 저장할 수 있습니다`). 지금 `허브에 넣기`가 이유 없이 흐림

### R3. 누르는 곳

- 모든 버튼·칩·목록 행 **최소 48dp**(지금 `Cw.Btn` 44dp), 주요 버튼(녹화 시작, 측정, 허브에 넣기, 지금 보내기)은 **56dp 이상**
- 버튼 사이 최소 8dp, 위험한 버튼(버리기·삭제)과 주요 버튼 사이 12dp 이상
- 슬라이더: 손잡이 24dp 이상, 누르는 범위 48dp, 막대 두께 6dp 이상. 옆에 `− / +` 버튼을 두면 장갑으로도 조절 가능(구조는 그대로, 기존 줄 안에 추가)
- 끌기(드래그)가 있는 곳은 **누르고 누르기** 대안이 이미 있음(A 배치, C 슬롯) → 덱에 두 방법을 같이 보여 줘 끌기가 필수가 아님을 분명히
- 모형 위 노드 점: 지름 36dp 이상, 선택되면 굵은 테두리 + 확대(지금처럼) + 아래 이름 표시

### R4. 색은 네 가지 뜻에만, 모드는 색으로 말하지 않는다

| 뜻 | 색 | 쓰는 곳 | 함께 쓰는 아이콘 |
|---|---|---|---|
| 주요·선택됨 | 파랑 | 주요 버튼, 선택된 칩, 기준 넘음(발동) | ● 채운 원 / ✓ |
| 정상·완료 | 초록 | 허브 연결됨, 바른 자세, 남긴 기록 | ✓ |
| 주의·경고 | **노랑-황토(앰버)** | 연결 불량, 배터리 부족, 이탈, 결정 필요 | ⚠ 삼각형 |
| 녹화·위험 | 빨강 | 녹화 버튼·녹화 중, 삭제 | ● 녹화 점 / 휴지통 |
| (상태 아님) | **회색** | 시뮬레이션 / 폰 센서 모드 칩, 동작 유형 배지 | 모드별 아이콘 |

v1에서 바꾼 이유
- **경고를 주황 → 앰버로**: 지금 주황 `#B4470F`와 녹화 빨강 `#B42318`은 색상이 거의 같아 색약이 아니어도 헷갈린다. 앰버는 밝기부터 달라 흑백에서도 구분된다
- **모드 칩을 회색으로**: `시뮬레이션` 칩이 늘 주황(경고색)이면 화면에 경고가 항상 떠 있는 셈이라 진짜 경고에 무뎌진다. 모드는 경고가 아니다
- **포즈형/교정형 배지를 회색 + 아이콘으로**: 지금 포즈형=파랑, 교정형=초록이라 "선택됨", "정상"과 뜻이 겹친다. 유형은 아이콘(손 들기 / 바른 자세)과 이름으로 구분
- 색만으로 상태를 말하지 않는다: 위 표의 아이콘과 글자를 항상 같이

### R5. 상태를 한눈에 (P3, P6)

- 화면이 바뀌는 순간 = 소리·진동이 나는 순간. 녹화 시작·끝, 측정 끝, 발동은 **소리 + 진동 + 화면** 세 가지가 같은 순간에(지금 구현된 `Feedback`과 맞춤). 경고 소리는 발동 소리와 음 높이로 구분
- 녹화 중·측정 중: 화면 테두리 또는 모형 카드 테두리를 그 상태 색으로 굵게(4dp), 카운트다운은 큰 숫자
- 판정 막대: 기준선을 막대보다 굵고 진하게(검정 4dp), 기준을 넘으면 막대 색 + 상태 글자 + 아이콘이 함께 바뀜
- 경고가 있는 행(결정 필요 기록, 연결 불량 노드): 옅은 앰버 배경 + 왼쪽 4dp 앰버 띠 + ⚠
- 경고는 **진짜 문제일 때만**. 상시 표시(모드, 유형)에는 경고색을 쓰지 않는다(R4)

### R6. 쉬운 말과 아이콘

- 아이콘만 있는 버튼 금지, 아이콘 + 글자(하단 탭은 이미 아이콘 + 글자)
- 화면에 보이는 말만 바꾸고 코드 이름은 그대로. 바꾼다면 짧고 평범한 말로(별명 같은 이름 금지)

| 지금 | 제안 | 이유 |
|---|---|---|
| 노드 | 센서 | 보호사가 실제로 부르는 말 |
| 허브 슬롯 | 허브 칸 1·2·3 | 슬롯은 낯선 말 |
| 포즈형 | 동작 신호 | 동작을 하면 신호가 감 |
| 교정형 | 자세 경고 | 자세가 무너지면 경고 |
| 민감도 / 발동 기준 | 발동 기준 | 슬라이더 이름은 짧게, 설명은 아래 한 줄 |
| 일치도 | 비슷한 정도 | 숫자 옆 `98% · 기준 85%`는 유지 |

- 용어를 바꾸면 `화면명세서.md`, `제안서.md`와 덱의 용어도 같이 맞춘다(시험 서술과 화면이 달라지지 않게)

### R7. 분위기

- 흰 카드 + 옅은 회청색 배경(지금 유지), 카드 모서리 16dp, 그림자 대신 1dp 테두리
- 신체 모형: 캐릭터·표정 없이, 선은 굵게(2dp) 면은 옅게. 사용하지 않는 부위는 지금처럼 흐리게
- 움직임은 상태 변화를 알릴 때만. 깜빡임은 초당 3번 미만(지금 노드 확인 깜빡임 확인 필요)

## 5. 권장 요구사항

- **어두운 테마**: 밤 병실용. 시스템 설정을 따르고(`values-night`), 같은 4가지 뜻을 어두운 값으로 한 벌 더
- **화면 꺼짐 방지**: 녹화·측정·D 테스트 중에는 화면이 꺼지면 안 됨(기능). 디자인에서는 따로 표시하지 않음
- 눌렀을 때 반응(눌림 색, 짧은 진동)을 모든 버튼에서 같게
- 안내 띠(5초 뒤 사라짐)는 글자가 커지면 다 읽기 전에 사라질 수 있음 → 글자 수에 따라 표시 시간 늘리기

덱 자체도 이 요구사항을 지킨다(작은 글씨·색만으로 구분 금지).

| # | 슬라이드 | 내용 |
|---|---|---|
| 1 | 표지 | 커맨드웨어 등록 앱 디자인 개선 · 돌봄 인력을 위한 화면 |
| 2 | 누가 쓰나 | 2장의 사용자 특성을 상황 그림으로(부축하며 한 손 조작, 밤 병실) |

| 9–13 | 화면별 전후 | A 노드, B 녹화, C 목록, D 테스트, E 출력 (같은 구조, 새 디자인) |
| 14 | 글자 130% · 어두운 테마 | D 화면 하나로 세 벌(100% / 130% / 어두운) |
| 15 | 검증과 구현 순서 | 7장 체크리스트 결과 + 무엇부터 고칠지 |

**구현 순서 제안**(효과 대비 수정량): ① 색 토큰 교체(`colors.xml`·`Ui.java`) ② 버튼 높이·글자 크기(`themes.xml`) ③ 경고 행·상태 아이콘 ④ 코드에서 정한 글자 크기 ⑤ 용어 ⑥ 어두운 테마

## 7. 검증 체크리스트

- [ ] 14sp 미만 글자가 없다(XML + 코드, `grep -rn "textSize\|setTextSize"`로 확인)
- [ ] 글자 대비 7:1(굵은 20sp 이상은 4.5:1), 테두리·막대 3:1 — Android **접근성 검사기(Accessibility Scanner)**로 A–E 캡처
- [ ] 모든 누르는 곳 48dp 이상, 주요 버튼 56dp 이상(같은 검사기가 알려 줌)
- [ ] 흑백으로 캡처해도 정상/경고/녹화/선택을 구분할 수 있다
- [ ] 글자 130%(`adb shell settings put system font_scale 1.3`)에서 A–D가 한 화면 구조를 유지하고, 1순위 글자가 잘리지 않는다(360dp 폭)
- [ ] 2m 떨어져서 D 화면의 발동·이탈 상태를 읽을 수 있다
- [ ] 아이콘만 있는 버튼이 없다, 흐린 버튼에는 이유가 있다
- [ ] 보호사·간병인 1–2명에게 "녹화를 시작해 보세요", "지금 경고가 떴나요?"를 묻고 바로 답하는지 확인

## 9. v1에서 바뀐 점

| v1 | 문제 | v2 |
|---|---|---|
| "회색 보조 글씨가 안 보인다" | 재 보니 6.3:1로 기본 기준(4.5:1)은 통과. 진짜 문제를 놓침 | 실제 불합격은 **테두리 1.55:1, 막대 2.0:1** → R2 표 |
| 대비 4.5:1 | 노안·밝은 조명에는 낮음 | 본문 7:1 |
| 경고 = 주황 | 녹화 빨강과 색상이 거의 같음 | 경고 = 앰버 |
| 시뮬레이션 = 주황, 폰 센서 = 초록 | 모드를 경고·정상으로 표시해 경고에 무뎌짐 | 모드·유형은 회색 + 아이콘 |
| 포즈형 = 파랑, 교정형 = 초록 | "선택됨", "정상"과 뜻이 겹침 | 유형은 아이콘 + 이름 |
| 16sp + 130%에서 구조 유지 | 둘이 부딪힐 때 기준이 없음 | 양보 우선순위 3단계 |
| 글자 크기는 XML만 셈 | 모형 위 글자 등 코드 10곳 누락 | 구현 범위에 Java 포함 |
| 목표만 있고 값이 없음 | 덱을 만들 때 다시 정해야 함 | 4장에 색 값과 대비 계산 |
| 용어 예시 "자세 지킴이" | 별명 같아 R7(차분함)과 어긋남, 문서와 화면 용어가 달라짐 | 평범한 말 + 문서도 같이 바꿈 |
| 검증 방법 없음 | 체크만 있고 어떻게 잴지 없음 | 접근성 검사기, `font_scale` 명령 |
| 소리·진동은 범위 밖 | P3에서 주 신호인데 빠짐 | R5에 화면과 같은 순간으로 |
| 표 안의 `11~22sp` | 마크다운에서 `~`가 짝을 이루면 취소선으로 보임(붙여 넣은 글에서 `1122sp`로 깨짐) | 범위는 `–`로 씀 |
