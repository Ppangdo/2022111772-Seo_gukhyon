# 커맨드웨어 등록 앱 화면 명세서

- 대상: 안드로이드 폰(세로), 보조자(보호자·치료사)가 사용
- 기준: `Main.dc.html` 목업(데스크톱 2단 배치)을 폰 한 화면에 맞게 다시 배치
- 상태: ✅ 구현됨 · 🔧 이번에 개선 · 📝 제안(아직 구현 안 함)

---

## 1. 편의성 원칙

목업은 1440px 가로 화면이라 모형과 설정을 나란히 놓았다. 폰에서 이것을 세로로 쌓기만 하면, 한 작업에 필요한 것들이 스크롤 위아래로 흩어진다. 아래 원칙으로 화면마다 무엇을 고정하고 무엇을 접을지 정한다.

| # | 원칙 | 이유 |
|---|---|---|
| P1 | **한 작업의 출발점과 도착점은 한 화면에** 둔다 | 끌어다 놓기·비교·판정은 둘 다 보여야 할 수 있다. 예) 미배치 노드 ↔ 신체 모형 |
| P2 | **작업대는 고정, 설정은 아래 시트로** 접는다 | 자주 하는 조작(배치·녹화·테스트)은 스크롤 없이, 가끔 바꾸는 값(보정·지연 시간)은 필요할 때만 펼친다 |
| P3 | **보조자는 폰이 아니라 사용자를 본다** | 녹화·테스트 중에는 화면을 보지 않아도 되게 소리·진동·큰 글씨로 알린다 |
| P4 | **엄지가 닿는 아래쪽에 주요 버튼** | 한 손으로 폰을 들고 다른 손으로 사용자를 부축하는 상황 |
| P5 | **실수는 되돌릴 수 있게** | 삭제·배치 해제·버리기는 확인 창 대신 "되돌리기"가 있는 알림으로 빠르게 |
| P6 | **지금 어디까지 했는지 늘 보이게** | 처음 쓰는 보조자도 다음에 할 일을 알 수 있게 |

## 2. 공통 요소

| 요소 | 내용 | 상태 |
|---|---|---|
| 헤더 | 한 줄: `커맨드웨어` + 허브 연결 칩 + 모드 칩 | 🔧 두 줄 → 한 줄로 줄여 작업 화면 높이 확보. ✅ 모드 칩(회색, `시뮬레이션 ▾` / `폰 센서 ▾`)을 누르면 **화면·입력 설정** 대화상자: 센서 입력(시뮬레이션/폰 센서), 글자 크기(작게/보통/크게), 화면(기기 설정/밝게/어둡게). 설정은 SharedPreferences에 저장 |
| 폰 센서 모드 | 실물 노드 없이 **폰 자체를 오른 아래팔 노드 하나로** 씀 | ✅ 아래 5장 참고 |
| 하단 탭 | A 노드 · B 녹화 · C 목록 · D 테스트 · E 출력 | ✅ |
| 안내 띠 | 동작 결과 알림("노드 04를 왼 윗팔에 붙였습니다") | ✅ 5초 뒤 자동으로 사라짐(노드 붙일 부위를 고르는 중에는 유지). 📝 되돌릴 수 있는 일(배치 해제·기록 버리기)에도 **되돌리기** 버튼 |
| 진행 체크 | 노드 배치 → 기준 자세 → 동작 1개 이상 → 허브 반영 | 📝 헤더 아래 얇은 4칸 표시, 누르면 해당 탭으로 이동 (P6) |
| 연결 끊김 | 허브·노드 연결이 끊기면 모든 화면 위에 빨간 띠 | 📝 실물 BLE 연결 단계에서 |
| 상태 저장 | 노드 배치·보정값·기준 자세 | 📝 지금은 앱을 다시 켜면 처음으로 돌아감 → SQLite 또는 SharedPreferences에 저장 |

## 3. 화면별 명세

### A. 노드 설정·보정

**목적**: 실물 노드를 몸에 붙인 위치를 모형에 똑같이 표시하고, 기준 자세와 체형 보정을 맞춘다.

**한 화면 고정 (작업대)** 🔧
- 신체 모형(남는 높이를 모두 사용), 앞/뒤 보기, 배치 수 `배치 3/4`
- 바로 아래 **미배치 노드 줄**(가로 스크롤) + `노드 추가`
- → 미배치 노드를 길게 눌러 모형으로 끌기, 모형의 노드를 줄로 끌어 해제 (P1)

**아래 시트** 🔧
- 접힘: `선택한 부위 · 왼 아래팔 · 노드 04 · 배터리 96% · 연결 불량`
- 펼침: 노드 정보 4칸, LED 깜빡이기, 배치 해제 / 개인 보정 슬라이더 3개 / 노드 흔들기 / 기준 자세 측정

**제안** 📝
- 노드를 끌기 시작하면 시트를 자동으로 접고, 놓을 수 있는 부위를 옅게 강조
- 실물 노드를 흔들면 모형의 점뿐 아니라 **미배치 줄의 칩도 같이 깜빡임**
- 배터리 20% 미만·연결 불량 노드가 있으면 헤더 칩을 주황색으로 바꿔 어느 탭에서든 보이게
- 기준 자세 측정은 3초 카운트다운을 **소리**로도 알림 (P3)

**폰 센서 모드** ✅
- 기준 자세 측정의 2초 동안 폰 센서 방향을 평균내 **기준(0°)으로 저장**. 상태 줄에 `선 자세로 측정함 · 07:56:17 · 폰 센서`
- 모형의 오른팔이 폰 움직임을 따라감

---

### B. 동작 녹화·검토

**목적**: 사용자가 같은 동작을 3~10번 하는 동안 녹화하고, 이상한 기록을 골라낸다.

**이전 문제**: 모형, 녹화 설정 6가지, 녹화 버튼, 기록 목록이 모두 세로로 쌓여서 녹화 버튼을 누르려면 스크롤해야 하고, 녹화 중 모형이 화면 밖에 있었다.

**한 화면 고정 (작업대)** ✅
- 신체 모형(녹화 중 움직임 표시, 쓰지 않는 노드는 흐리게), 카운트다운 원
- 설정 요약 한 줄: `오른팔 들기 · 포즈형 · 노드 02·03 · 지연 3초 · 1초` → 누르면 시트 펼침
- 진행 막대 `남긴 기록 3개 · 최소 3 · 권장 10`, 경고 기록이 있으면 `⚠ 결정 필요 1개 ›` (누르면 시트를 열고 그 기록으로 스크롤)
- 화면 아래 **큰 녹화 버튼**(엄지 위치, P4): `4번째 녹화 시작` / `3초 후 시작` / `녹화 중` + 옆에 `허브에 넣기`

**아래 시트** ✅ (처음엔 숨김, 녹화를 시작하면 자동으로 닫힘)
- 기록 목록(다시 보기 / 남기기 / 버리기) — 다시 보기를 누르면 시트를 닫고 모형으로 재생
- 저장 버튼 `폰에 저장` · `허브에 넣기`
- 녹화 설정(이름, 트리거 방식, 사용 노드, 시작 지연, 녹화 길이, 일치 기준)

**구현한 편의 기능** ✅
- **사용 노드는 모형에서 바로 고르기**: 모형의 노드를 누르면 켜고 끔 (P1)
- **사용 노드를 바꾸면 녹화한 기록을 모두 지움**: 노드 구성이 다르면 기록끼리 비교할 수 없으므로. 안내 띠 `사용 노드를 바꿔서 녹화한 기록 2개를 지웠습니다` (📝 되돌리기는 아직)
- 카운트다운·녹화 시작·끝을 **삐 소리 + 진동**으로 알림, 경고 기록은 다른 소리 (P3) — 기준 자세 측정에도 적용

**폰 센서 모드** ✅
- 카운트다운·녹화 중 모형이 실제 움직임을 따라감
- 일치도를 고정 숫자 대신 계산: 녹화 중 **최고 팔 각도**(포즈형) 또는 **최대 상체 기울기**(교정형)를 대표 기록(남긴 기록 중 최고)의 값과 비교, 1° 차이마다 1.2%씩 깎음. 대표 기록이 없으면 목표 자세(팔 150°, 기울기 0°)와 비교
- 다시 보기는 그 기록의 실제 최고값으로 재생
- 📝 지금은 최고값 하나만 비교 → 시간에 따른 곡선 전체를 비교(DTW 등)하면 "빨리 들었다 내림"과 "천천히 들기"도 구분 가능

**남은 제안** 📝
- **연속 녹화**: 한 번 누르면 "지연 → 녹화 → 2초 쉼"을 정한 횟수만큼 반복 (보조자가 매번 폰을 누르지 않게)
- **볼륨 키로 녹화 시작**: 화면을 보지 않고도 시작 (P3, P4)
- 저장하면 C로 바로 넘어가는 대신 `저장했습니다 · 테스트해 보기 →` 선택지

### C. 동작 목록

**목적**: 폰에 저장한 동작 중 3개를 골라 허브 슬롯에 넣고, 허브에 반영한다.

**한 화면 고정** ✅
- 위: 동기화 상태 `바뀐 내용이 허브에 아직 반영 안 됨 · 지금 보내기` + **허브 슬롯 3칸을 작게 가로로** (`슬롯 1 · 트랙 1`, 이름, 유형 배지)
- 아래: 폰에 저장된 동작 목록(리스트뷰, 이 부분만 스크롤)
- → 목록의 동작을 **길게 눌러 슬롯 칸으로 끌어 넣기/교체** (P1). 칸에 올리면 파랗게 표시. 원래 있던 동작은 폰에 남는다는 안내
- 기존 "허브에 넣기" 버튼과 "교체할 슬롯 고르기"도 그대로 쓸 수 있음

**구현한 편의 기능** ✅
- 슬롯 칸을 누르면 그 동작의 상세(녹화 추가·테스트·출력 연결·허브에서 빼기)를 시트로
- **삭제 + 되돌리기** (P5): 확인 창 대신 바로 지우고 6초 동안 `되돌리기` 알림. 처음엔 기본 2.75초였는데 테스트해 보니 너무 짧아서 늘림

**남은 제안** 📝
- 목록에서 옆으로 밀어 삭제
- 기준 자세가 다른 동작은 목록에서 흐리게 (지금은 `⚠ 현재 기준 자세와 다릅니다` 문구만)
- 허브 반영이 안 된 상태로 D 탭에 가면 `허브에 아직 반영 안 됨` 안내

### D. 실시간 테스트

**목적**: 허브에 넣은 동작이 의도대로 발동하는지, 평소 움직임에 잘못 발동하지 않는지 확인한다.

**이전 문제**: 흉내 버튼 → 모형 → 판정 막대 → 발동 기록 순서로 쌓여 있어서, 버튼을 누르면 판정 막대가 화면 밖이었다.

**한 화면 고정** ✅
- 위: 흉내 버튼 한 줄 `폰 센서 · 오른팔 들기 · 허리 굽히기 · 평소 움직임 · 가만히` — ✅ `폰 센서`를 누르면 목표값 대신 실제 폰 센서 값으로 판정·발동(포즈형·교정형 모두). 센서가 없는 기기에서는 버튼이 흐리고, 누르면 이유를 토스트로 알림. 📝 실물 노드 연결 후에는 "실제 센서" 표시로 바뀜
- 가운데: **모형(왼쪽) + 슬롯 3개 판정 막대(오른쪽)** 나란히. 막대에 기준선, `98% · 기준 75%`, 상태(`대기` / `기준 넘음` / `바른 자세` / `이탈 1.2/1.5초`)
- 아래: **최근 발동 한 줄** `05:17:31 자세 이탈 경고 · 바른 앉은 자세 · 소리 모듈 · 트랙 2  기록 1 ›`
- 발동 순간: 모형 위 배너 + 삐 소리 + 진동 (P3)

**아래 시트** ✅ (처음엔 숨김)
- **판정 막대를 누르면** 시트가 열리고 그 슬롯의 민감도 슬라이더로 바로 스크롤
- 최근 발동 줄을 누르면 발동 기록(최근 8개)으로 스크롤
- `출력 실제 보내기` 스위치
- ✅ **허브 동작 켜기·끄기**: 슬롯마다 스위치(`켜짐`/`꺼짐`). 끈 동작은 판정·발동하지 않고, 판정 행은 `○ 꺼짐 · 판정 안 함`·빈 막대로 흐리게 표시. 다른 동작만 따로 시험할 때(예: 팔 들기만) 사용. 앱을 다시 켜도 유지(SharedPreferences)

**남은 제안** 📝
- **오발동 표시**: 발동 기록에서 "이건 잘못 발동" 표시 → 민감도 올리기 제안
- 평소 움직임 1분 테스트 버튼: 1분 동안 발동 횟수를 세서 `오발동 0회 ✓` 결과 표시
- 포즈를 계속 유지하면 3초마다 다시 발동해 기록이 빨리 쌓임 → "자세를 풀었다가 다시 해야 발동" 옵션

---

### E. 출력 연결 (다음 단계)

**목적**: 동작마다 어떤 수신 모듈·포트로 신호를 보낼지 정한다.

**한 화면** 📝
- 왼쪽 열: 허브 슬롯 3개 / 오른쪽 열: 출력(소리 트랙 1~3, 모터, LED, 키 입력)
- 슬롯과 출력을 **선으로 연결**(누르고 누르기) — 지금은 "슬롯 번호 = 트랙 번호" 고정
- 출력마다 `테스트 신호` 버튼으로 바로 확인

| 순위 | 개선 | 화면 | 원칙 | 수업 내용 |
|---|---|---|---|---|
| 1 | ✅ 모형 + 미배치 노드 한 화면, 설정 시트 | A | P1 P2 | 레이아웃, 커스텀 뷰 |
| 2 | ✅ B 작업대 고정 + 큰 녹화 버튼 + 설정 시트 | B | P1 P2 P4 | 레이아웃 |
| 3 | ✅ 모형에서 사용 노드 바로 고르기 | B | P1 | 터치 이벤트 |
| 4 | ✅ D 모형·판정 막대 나란히, 막대 눌러 민감도 | D | P1 P2 | 레이아웃 |
| 5 | ✅ 녹화·측정·발동 소리와 진동 | A B D | P3 | `Vibrator`, `ToneGenerator` |
| 6 | 노드 배치·보정값 저장 | A | P6 | 12장 SQLite |
| 7 | ✅ 삭제 되돌리기 알림(스낵바), 안내 띠 자동 사라짐 · 📝 다른 화면에도 되돌리기 | C · 공통 | P5 | 7장 메뉴·토스트·대화상자 |
| 8 | 진행 체크 4칸 | 공통 | P6 | 10장 화면 이동 |
| 9 | ✅ 목록 → 슬롯 끌어 넣기, 슬롯 상세 시트 | C | P1 | 11장 리스트뷰 |

## 5. 폰 센서 모드 (구현 메모)

**목적**: 하드웨어 노드 없이도 시연 때 폰을 팔에 대고 실제로 움직이면 판정이 반응하게 한다.

| 항목 | 내용 |
|---|---|
| 구조 | `SensorService`(바인딩 서비스). `MainActivity`가 **화면이 보이고(onStart~onStop) 폰 센서 모드일 때만** `bindService`, 아니면 `unbindService`. 서비스는 `onBind`에서 센서 등록, `onUnbind`에서 해제 → 배터리 낭비 없음 |
| 값 전달 | 바인더로 받은 서비스에 콜백을 넘기고, 센서 값이 올 때마다 `AppState.onPhoneTilt()` 호출. 같은 앱 안이라 브로드캐스트보다 바인딩이 단순하고 빠름(초당 50번) |
| 센서 | `TYPE_GAME_ROTATION_VECTOR` → 없으면 `TYPE_GRAVITY` → `TYPE_ACCELEROMETER`. 회전 행렬 셋째 행(세계의 '위쪽'을 기기 좌표로)을 저역통과 필터(α 0.3, 가속도는 0.15)로 다듬음 |
| 계산 | 폰 세로축(y)이 위쪽과 이루는 각도. 손목을 돌려도(세로축 기준 회전) 값이 거의 안 바뀜. 기준 자세 각도와의 차이 θ를 씀 |
| 해석 | 노드가 하나라 팔 들기·상체 숙이기를 **각도 범위로 나눔**: θ < 45° → 상체 숙임(`lean` = (θ−8)/27, 35° 이상이면 1), θ ≥ 45° → 팔 들기(`armR` = 4+θ, 최대 150°). 45~70°에서는 숙임 해석을 서서히 줄임 |
| 발동 기준 | 오른팔 들기(민감도 85%): 팔 약 123° 이상 → **머리 위로 들어야** 발동. 바른 앉은 자세(75%): 약 18° 이상 1.5초 숙이면 경고 |
| 확인 | 에뮬레이터 `adb emu sensor set acceleration x:y:z`로 팔 내림(0:-9.8:0)·들기(0:9.8:0)·숙임 25°(0:-8.88:4.14) 넣어 D 발동 두 가지, A 측정, B 일치도(150° 기록 뒤 124° 기록 → 69% 경고) 확인 |

**남은 일** 📝
- 숙임과 팔 들기를 진짜로 구분하려면 노드가 2개 필요(가슴 + 팔). 폰 두 대를 쓰거나 실물 노드 연결 후
- ✅ 기준 자세(`tilt0`)·폰 센서 모드를 SharedPreferences(`cw_phone`)에 저장 → 앱을 다시 켜도 유지
- ✅ 폰 센서 모드·D 화면·녹화·측정 중에는 화면 켜짐 유지(`FLAG_KEEP_SCREEN_ON`) → 시연 중 화면이 꺼져 센서가 멈추는 일 방지
- ✅ D 화면에서 바로 **기준 잡기**(폰 센서 모드일 때만 보임): 누르고 5초 카운트다운(삐 소리) 동안 폰을 팔에 대고 팔을 내리면 2초 평균을 0°로. 상태 줄 `✓ 폰 센서 · 기준 03:07:40` / `⚠ 기준 자세를 먼저 잡으세요`
- 📝 실제 폰(자이로 있음)에서 반응 속도·발동 각도 확인
- 📝 팔을 아주 천천히 들면 중간 각도(8–45°)에서 1.5초가 지나 이탈 경고가 먼저 뜰 수 있음 → 각도가 빠르게 변하는 중에는 교정형 판정을 잠시 멈추기
- 📝 포즈형은 녹화 내용과 상관없이 '팔 들기'로 판정(시연은 기본 동작 두 개로)
- 서비스가 화면이 꺼지면 멈춤 → 실제 제품처럼 화면 없이 감지하려면 포그라운드 서비스 + 알림
